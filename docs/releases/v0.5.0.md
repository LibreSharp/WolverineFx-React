Integrations for `--Auth saas` (API keys, an MCP endpoint for AI assistants, webhooks and
encrypted secrets), and notifications and "Download your data" for every app with accounts.

## Changes to know about

- **The realtime connection is shared by the whole page.** `lib/realtime.ts` owns the tab's one
  SignalR connection, and components listen with `useRealtime(onMessage, onResync)`.
  `useTodoRealtime` is built on it; code that copied its old connection setup should switch.
- **The header has a notifications bell** beside the user menu (with accounts), and the user
  menu's button is marked `data-menu="account"` (the end-to-end tests use it).
- **`EmailMessage` has an optional `UnsubscribeUrl`,** which `SmtpEmailSender` sends as the
  `List-Unsubscribe` headers. Custom `IEmailSender`s should do the same for notification emails.
- **EF Core:** new migrations add notifications (`identity` and `saas`) and integrations (`saas`).
- **New package** with `saas`: `ModelContextProtocol.AspNetCore` (the official C# MCP SDK,
  Apache-2.0).

Projects created from earlier versions don't change: a template update only affects new projects.

## New

- **API keys** (`saas`): owners and admins create, rotate and revoke keys on the organisation's
  Integrations page. A key (`Authorization: Bearer sk_...`) acts as its creator in its
  organisation, with a read or read-and-write scope and a rate limit, and only reaches the paths
  it's for (`ApiKeys:AllowedPaths`). Only a hash is stored.
- **MCP** (`saas`): `/mcp` serves the Todos as tools (`list_todos`, `add_todo`, `complete_todo`)
  for AI assistants, with an API key, following the API's rules (validation, plan limits,
  realtime updates, webhooks).
- **Outgoing webhooks** (`saas`): signed the Standard Webhooks way, sent from a durable queue with
  retries for about 10 hours, logged with the receiver's answer, with resend and test events.
  Never to localhost or private networks in production. Todo created and completed are the
  example events; add more with `WebhookEvents.Raise`.
- **Secrets** (`saas`): owners store keys and tokens for other services, encrypted with Data
  Protection and never shown again; the app reads them with `OrganisationSecrets.GetAsync`.
- **Receiving webhooks** (`saas`): `POST /api/webhooks/incoming/{source}` for any Standard
  Webhooks provider, configured with `Webhooks__Incoming__Secrets__<source>`.
- **Notifications** (accounts): reminders (and, with `saas`, people joining an organisation you
  manage) appear under a bell in the header, live, and are emailed unless turned off in
  Settings or with the email's one-click unsubscribe link. Publish `SendNotification` to add more.
- **Download your data** (accounts): Settings downloads everything stored about the user as JSON;
  with `saas`, owners download their organisation's data. Features add sections with
  `IPersonalDataSource` and `IOrganisationDataSource`.

See the generated app's `docs/integrations.md` and `docs/accounts.md`.
