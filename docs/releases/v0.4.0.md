Organisations: `--Auth saas` adds multi-tenancy, with members, roles and invitations. The public
pages are now pre-rendered.

## Breaking changes

- **`--Identity` is replaced by `--Auth none|identity|saas`.** Use `--Auth identity` where you
  used `--Identity true`, and `--Auth none` (the default) for `--Identity false`.
- **With accounts, production needs `App__ClientUrl`.** Set it to the app's public address, such
  as `https://app.example.com`. Email links (confirmation, password reset, invitations) and the
  redirect after Google or GitHub sign-in are built from it, never from the request's `Host`
  header. The app won't start without it outside Development. The production
  `deploy/docker-compose.yml` sets it from `DOMAIN`; set it yourself anywhere else.

Projects created from earlier versions don't change: a template update only affects new projects.

## New

- **Organisations (`--Auth saas`)**, on Marten or EF Core:
  - Each organisation is a Wolverine tenant. The access token names the organisation the user
    works in, and conjoined multi-tenancy keeps each organisation's data apart in the data
    layer, with no filters to forget.
  - Every account gets its own organisation. Users can create more, switch between them in the
    header, and be invited into others.
  - Owner, Admin and Member roles, with always at least one owner.
  - Invitations by email. Someone with an account accepts after logging in; someone without one
    creates their account from the link. Invitations are limited per user and per organisation.
  - Removing a member, or deleting the organisation, takes effect at once. Deleting an
    organisation deletes its data, including Todo event history.
  - Realtime updates go to everyone working in the organisation, and reminders only to whoever
    set them.
- **Pre-rendered public pages** with React Router's framework mode:
  - The home page is real HTML at build time, for search engines, link previews and CDN caching.
  - The Content-Security-Policy allows only the build's own inline start-up scripts, by hash.
  - It's still one deployable, with no Node server.
- **Code layout:**
  - Code that differs between Marten and EF Core is in `Name.Marten.cs` / `Name.EfCore.cs`
    pairs, renamed to `Name.cs` in generated apps.
  - Account endpoints are features: `Features/Auth`, `Features/Account` and `Features/Admin`.
- CI generates, tests and publishes all 12 option combinations.

## Fixed

Found by an architecture review before release. The details are in
[the review](https://github.com/LibreSharp/WolverineFx-React/blob/v0.4.0/docs/reviews/v0.4.0-architecture-review.md).

- Email links no longer use the request's `Host` header. A forged host could send a password
  reset link to another site. This affected earlier versions too.
- SignalR connections close when their access token expires, and the browser reconnects with a
  fresh token. A removed member, or a locked account, no longer keeps receiving live updates.
